# Minef — плагин с виртуальным игроком внутри сервера

Паper/Spigot-плагин, который сам создаёт "виртуального игрока" (реальное
сетевое подключение как ещё один клиент, через библиотеку MCProtocolLib) и
подключает его к тому же серверу через `127.0.0.1`. Управляется командами:

- `/minef start` — подключить виртуального игрока
- `/minef stop` — отключить
- `/minef status` — проверить, подключён ли сейчас
- `/minef say <текст>` — отправить сообщение (без `/`) или команду (с `/`)
  от его имени. Это тот же чат-пакет, что и обычное сообщение — Minecraft
  сам разбирает текст с `/` как команду, отдельно ничего кодировать не нужно.

## Сборка через GitHub Actions (рекомендуется)

В репозитории уже есть workflow `.github/workflows/build.yml`, который:

1. Клонирует ветку `feature/26.2` репозитория `GeyserMC/MCProtocolLib`
2. Собирает её и публикует в `~/.m2` (кеш раннера)
3. Собирает сам плагин через `mvn clean package`
4. Выкладывает готовый `minef.jar` как build-артефакт

Просто залейте это в свой репозиторий на GitHub (или форкните), запустите
workflow вручную (вкладка Actions → Build Minef plugin → Run workflow)
или сделайте push — и заберите готовый jar из артефактов запуска, без
локальной сборки Gradle/Maven у себя на машине.

Дальше от лица этого виртуального игрока вы можете выполнять:
```
/minef say /dvc group create discord-bridge "" persistent
/minef say /dvc start
```
и это будет воспринято сервером и плагином voicechat-discord (или его
форком) как обычные команды реального игрока.

## Диагностика "зависания" в фазе CONFIGURATION

Если после `/minef start` бот подключается, но никогда не появляется в
`/list` и команды вроде `/gamemode` пишут "Игрок не найден" — значит он
застрял на каком-то этапе протокола, ожидающем ответ клиента. В
`BotSession.java` уже реализована отправка всего, что реальный клиент
шлёт сам, без запроса сервера, а библиотека - нет:

- **Client Information** (локаль/настройки) и **brand** ("vanilla") —
  сразу при входе в CONFIGURATION
- **Code of Conduct** — новый в 26.x обязательный пакет-подтверждение
  правил сервера, автоматически принимается
- **Resource Pack** — если сервер присылает ресурспак, бот сразу
  отвечает "успешно загружен", ничего реально не скачивая
- **Login plugin-запросы** (`CustomQuery`) — на любой незнакомый канал
  от плагинов отвечаем пустым результатом, чтобы не блокировать логин
- **Ping/Pong** — отвечаем на пинг сервера

Если после всего этого бот всё ещё не заходит в игру - остаётся
единственный правдоподобный вариант: какой-то плагин требует **свой**
клиентский мод и устраивает собственный хендшейк через plugin-канал
(как было с Emotecraft - см. историю переписки). Тут поможет только
метод исключения - отключайте по одному "подозрительные" плагины
(всё, что завязано на визуал/клиентские моды - вроде CDisc, TAB,
Morphy, LibsDisguises, ImageFrame), пока бот не зайдёт полностью.

## Об API этой ветки (важно)

Код в `BotSession.java` написан по **реальным исходникам** ветки
`feature/26.2` (склонировал её и сверился напрямую, а не гадал). Пара
важных нюансов:

- Команды (текст с `/`) уходят отдельным, простым пакетом
  `ServerboundChatCommandPacket` — с ними никаких сложностей нет, и это
  как раз наш основной сценарий (`/dvc start`, `/dvc group ...`).
- Обычные сообщения чата (без `/`) в этой версии протокола требуют
  полей подписи сообщения (timestamp/salt/signature/...) — часть
  механизма защищённого чата Minecraft. Сейчас они отправляются **без**
  подписи (`signature = null`). Это может не сработать на серверах с
  принудительной secure chat проверкой — просто имейте это в виду, если
  `/minef say <текст без слэша>` не будет доходить до чата на некоторых
  серверах. Для команд эта проблема не актуальна.

## Сборка (под Paper 26.2)

Нужны **JDK 25+** (Paper 26.2 требует именно 25-й) и Maven.

`pom.xml` уже настроен под 26.2:
- `paper-api` берётся диапазоном `[26.2.build,)` — Maven сам подтянет
  последний опубликованный билд под эту версию (официальная схема
  PaperMC начиная с 26.x, без старого суффикса `-R0.1-SNAPSHOT`)
- `plugin.yml` → `api-version: '26.2'`

⚠️ Библиотеки `org.geysermc.mcprotocollib:protocol` под 26.2 в Maven пока
нет, но в официальном репозитории есть ветка **`feature/26.2`** с этой
работой (https://github.com/GeyserMC/MCProtocolLib/tree/feature/26.2).
Собираем её и публикуем в свой локальный репозиторий (Maven сам смотрит
в `~/.m2/repository` перед обращением к удалённым репозиториям, отдельно
прописывать `mavenLocal()` в `pom.xml`, в отличие от Gradle, не нужно):

```
git clone --branch feature/26.2 https://github.com/GeyserMC/MCProtocolLib
cd MCProtocolLib
./gradlew publishToMavenLocal
```

После сборки посмотрите в консольном выводе (или в
`~/.m2/repository/org/geysermc/mcprotocollib/protocol/`), какая именно
версия опубликовалась — обычно она берётся из `gradle.properties` той
ветки. В `pom.xml` сейчас стоит `26.2-SNAPSHOT` как ожидаемое значение —
если реальная версия окажется другой, поправьте на неё.

Если сборка из этой ветки не заработает с первого раза (нестабильная
feature-ветка, может что-то ломаться) — падать назад на вариант с 26.1
(см. предыдущий совет) всё ещё остаётся самым надёжным запасным планом.

1. Клонируйте ветку `feature/26.2` и соберите её как выше
2. Откройте `pom.xml`, при необходимости поправьте версию
   `org.geysermc.mcprotocollib:protocol`
3. `mvn clean package`
4. Готовый jar будет в `target/minef.jar`

## ⚠️ Важные оговорки — прочитайте перед использованием

1. **Это черновик, а не готовый к продакшену плагин.** Точные имена
   классов/пакетов MCProtocolLib менялись между версиями. Возможно,
   `BotSession.java` потребует правок под конкретную версию библиотеки,
   которую вы подставите в `pom.xml` — прежде всего класс для отправки
   чат-пакета и путь до него.
2. Если сервер в **онлайн-режиме** (не крек), виртуальному игроку
   тоже потребуется настоящая авторизация Microsoft — просто как для
   Mineflayer-варианта. Если сервер в offline/cracked-режиме — сработает
   с произвольным именем.
3. Виртуальный игрок появляется в мире как настоящий (со скином, тегом
   ника, физикой) — на него будут действовать анти-афк/анти-чит плагины,
   мобы, и т.д. Возможно, потребуется поставить его в креатив/спектатор
   и в безопасную зону от имени оператора после подключения через
   `/minef say /gamemode spectator` (если permissions это позволяют
   игроку-боту).
4. Так как бот подключается как отдельный сетевой клиент **внутри той же
   JVM**, что и сервер, убедитесь, что это не создаёт лишней нагрузки —
   для одного голосового моста это несущественно.
5. Я не могу скомпилировать и протестировать этот код в своей текущей
   среде (нет доступа к репозиторию Maven с этой библиотекой) — считайте
   это рабочим каркасом, который почти наверняка потребует одной-двух
   правок при первой сборке под вашу версию сервера.
